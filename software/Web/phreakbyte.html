      S3Slot type & enable
      
    
      
      
      
        
        
        
        
        
      
      
      
      
        
        
        
        
      
      
      
      "Delete {sense} data in slot" wipes just the HF or LF tag data for that slot (per the Sense dropdown above) without touching the other sense or the slot's nickname — use it to clear a slot's old tag before reusing it with a different type.
      
      
      Common tag type codes
        
      LF 100 EM410X · 104 EM410X_ELECTRA · 150 PAC · 170 Viking · 180 Jablotron
LF 200 HIDProx · 201 ioProx · 310 IDTECK · 311 Indala
HF 1000 MIFARE_Mini · 1001 MIFARE_1024 (1K) · 1002 MIFARE_2048 (2K) · 1003 MIFARE_4096 (4K)
HF 1100 NTAG_213 · 1101 NTAG_215 · 1102 NTAG_216 · 1103 MF0ICU1 · 1105 MF0UL11 · 1106 MF0UL21
HF 1300 DESFire EV1 2K · 1301 DESFire EV1 4K · 1302 DESFire EV1 8K
HF 1303 DESFire EV2 2K · 1304 DESFire EV2 4K · 1305 DESFire EV2 8K
      
      
      
      
      The DESFire tab needs the active slot's HF type set to one of the DESFire codes above. On a slot that's never held DESFire data, "Set slot tag type" alone is not enough — the device only reloads existing flash data, and there is none yet. You also need this slot to be the active slot (Set active slot) before "Set slot data default", since that's the step that only writes live if the slot is already active. See DESFire tab → F0 for a one-click helper that does this in the right order.

      H10Raw ISO14443A bytes

This is HF14A_RAW (not the DESFire tab's F4, which only talks to the active slot's own DESFire emulation).
      
      
      
        
        
        
        
        
        
      
      
      
      
        
        
        
      
      
      
      
    
      

    
      H11MF1 value block (increment / decrement / restore)
      
    
      
      
      Authenticates against a source block, runs the value-block operation, then (if different) authenticates the destination block and transfers the result into it. Source = destination is the common case (operate in place).
      
      
      
        
        
        
      
      
      
      
        
        
      
      
      
      
        
        
        
        
      
      
      
      
    
      

    
      H12Magic auth (gen1a-style raw auth, reader mode)
      
    
      
      
      Sends a raw backdoor auth command (e.g. 0x80 for GDM/gen1a magic cards) directly to the RC522, bypassing the normal MF1 authenticate flow. Ultra only — not available on Lite.
      
      
      
        
        
        
        
        
      
      
      
      
    
      

    
      H13ISO14443-4 (T=CL) emulation — static APDU responses
      
    
      
      
      Low-level building block behind this fork's EMV/smartcard emulation profile: canned responses keyed off the incoming command bytes, plus manual anti-collision data (UID/ATQA/SAK/ATS) and a one-shot push/poll pair for a custom reader loop.

      F0Prepare a slot for DESFire
      
    
      
      
      
        
        
        
      
      
      
      GET_INFO / GET_CREDENTIAL / FACTORY_BLANK act on a live in-RAM buffer, not on the slot's flash record directly. Set slot tag type alone only tries to reload that buffer from an existing flash record — on a slot that's never held DESFire data there is none yet, so the buffer stays empty and every DESFire command keeps returning PAR_ERR. Set slot data default writes the factory record to flash, but only reloads the live buffer immediately if the slot is already the active slot — otherwise the record sits on flash until the slot is activated. This button runs the three steps in the one order that always works: set tag type → make this the active slot → set slot data default (now live). Do this once per slot before using F1-F3 below.

      F4Real card — raw command & auto-dump
      
    
      
      
      Note
      
      
      All of F3/F4 needs the device itself in Reader mode (Device tab → Device mode), not Tag/emulation mode — that's a separate requirement from the slot prep in F0, which only matters for the emulated side. Auto-dump only reads files whose comm_settings is plain (0x00, no secure messaging) and only applications/files the card lets you see without authenticating first — encrypted/MAC'd files and anything gated behind auth are reported, not read. This talks to native DESFire command bytes directly (dfc_command.c / dfc_common.h in the fork), wrapped as 90 INS 00 00 [Lc data] 00 over HF14A_4_READER_APDU.
      
      
      Known limit: HF14A_4_READER_APDU re-selects the card (full antenna-off/reset/RATS) on every call, so it can't carry a multi-frame reply (native status 0x91/0xAF) — you'll get a clear error instead of silent garbage; use F3's GetVersion button for that one case, and keep ReadData/ReadRecords lengths short enough to fit one frame. Unverified: whether SelectApplication's effect survives into the next separate call (same re-select-per-call behavior) is not something I could confirm from source alone — if auto-dump's files all come back as if nothing were selected (wrong AID's files, or application-not-found), that's the likely reason; the raw sender above is the way to test SelectApplication followed by GetFileIDs by hand.
      
    
      
    
      
      
      
        
        
      
      
      
      
        
      
      
      
      Common INS: 60 GetVersion · 51 GetCardUID · 6A GetApplicationIDs · 5A SelectApplication (3B AID) · 6F GetFileIDs · F5 GetFileSettings (1B file no) · BD ReadData (file no + 3B offset + 3B length, 0/0=all) · 6C GetValue (1B file no) · BB ReadRecords (file no + 3B record no + 3B count, 0/0=all).
      
      
      
    
      
    
      
      
      
        
      
      
      
      Walks GetApplicationIDs → SelectApplication → GetFileIDs → GetFileSettings → reads whatever's readable without auth. Place the card in the field first.
      
      
      
    
      
  
      

  
  
      
    
      
      
      Note
      
      
      Ported from this fork's emv scan CLI command (chameleon_cli_unit.py), built on the firmware's single-call HF14A_4_EMV_SCAN (6005) — the whole PPSE → SELECT AID → GPO → READ RECORD sequence runs inside one firmware call with the field held continuously, so it doesn't hit the per-call-reselect problem DESFire's generic reader path does. Needs the device in Reader mode (Device tab). Place a contactless EMV card (bank card) on the antenna first.
